# iCanvas architecture

13 November 2026. [Decisions and licences](ICANVAS_DECISIONS.md) · [Interface references](ICANVAS_REFERENCES.md) · [Export verification](ICANVAS_EXPORT_QA.md)

## Entry points and local boundary

Croft serves the existing React and TypeScript shell at `http://localhost:5173` using Vite. The server binds to `localhost` and fails if 5173 is already in use. The local server must be running to open or reload the app. App code and media load locally. The document policy permits same-origin scripts, local image/media resources, and frames from only YouTube's privacy-enhanced host and the official X widget host. Croft does not load third-party scripts in its privileged document. Those cross-origin frames are created only after an explicit permission choice. Use the same protocol, hostname, port, and browser profile to reopen the same IndexedDB workspace. Switching to `127.0.0.1` opens a distinct origin. [Vite config](../vite.config.mjs) · [Content Security Policy](../index.html) · [Browser origin rules](https://html.spec.whatwg.org/multipage/browsers.html#concept-origin)

Home, the sidebar's separate project tree, breadcrumbs, and global search open the same `#canvas/<id>` route. The five utility entries remain part of the Croft shell. `App.tsx` owns navigation and sidebar state, `ProjectViews.tsx` owns Home cards, tree rows and project metadata, and `CanvasWorkspace.tsx` coordinates the canvas. On entry Croft collapses the main sidebar, which can still be toggled in the canvas. [Croft shell](../src/App.tsx) · [Project views](../src/features/icanvas/ProjectViews.tsx)

## Scene and editing state

| Layer | Responsibility |
| --- | --- |
| `model.ts` | Project and object UUIDs, project and object parent links, canvas targets, asset references, typed edges, per-project camera and settings, and presentation stops. Names are editable display text. Object flags inherit hidden and locked state from ancestor containers. |
| `geometry.ts` | World and screen coordinates, pointer-anchored wheel and pinch zoom, rotated bounds, fit, equal-gap snapping, frame growth and nested similarity transforms. Zoom is bounded to 0.25–6,400%. Canvas CSS and SVG coordinates rebase near the viewport while durable world coordinates remain unchanged. |
| `CanvasWorkspace.tsx` | React pointer and keyboard coordination, tool modes, drag/resize/rotate drafts, snapping, marquees, connections, context menus, camera, minimap, playback and export entry. Transient state remains in the mounted workspace. The saved camera and toolbar settings belong to the project. |
| `CanvasVisuals.tsx`, `CanvasInspector.tsx` | DOM media and text, thumbnail previews, Layers, and selected-object properties. Edge and stroke drawing use SVG. Visible media mounts with the scene and its object URLs are revoked on cleanup. |
| `CardFaces.tsx`, `stackScene.ts`, `stackPersistence.ts` | The flip tab and Back editor, stack commands and scene projection, and structural validation of card and stack data across writes and reimports. |
| `history.ts`, `useCanvasEditing.ts` | Local undo/redo records before/after object and edge snapshots. Multi-object gestures undo as a single action. The history retains up to 50 actions per object and lives in memory. |

Notes and card-display objects keep their original fields as the Front. Optional `back` fields hold a title, text and one local attachment reference. `face` records the visible side. The object keeps its ID and geometry. Switching a media item to Direct display retains the stored Back. Only the visible face mounts or receives focus. Changing faces pauses and unmounts hidden media. Returning to it leaves playback stopped. A read-only tab can inspect either side without writing the preference.

A stack stores its name and anchor on a container object. Its ordered member IDs and each member’s `parentId` agree. The model retains member geometry in world coordinates. Rendering centres the active card at the anchor and projects at most three rear silhouettes. Fan Out projects all members in a grid. Stack moves and enclosing frame/group transforms update canonical geometry once. Obscured connections route to projected points on the pile while retaining the original member IDs. Stack creation and deliberate Add to Stack require loose cards with the same immediate parent. Layers exposes the entire order.

The editor builds a per-scene RBush index of rotated visible bounds. A screen-space viewport padded by 100 px is projected into world coordinates for each query. The visible subset is rendered in object order, with active drag drafts included even when they move beyond the original indexed bounds. The index rebuilds when the object array changes. Panning and zooming query the existing index. Large viewport fills can still render many elements at once, and bulk edits rebuild the index on the main thread. The implementation has no established object-count or frame-rate guarantee. [Scene renderer](../src/features/icanvas/CanvasWorkspace.tsx) · [Geometry](../src/features/icanvas/geometry.ts)

## Image edits and project swatches

The project stores immutable image edit settings per object or per Back attachment. The same source asset can be reused by independently edited images. The editor keeps in-progress control values and Compare Original in memory. A completed edit uses the owning object's regular undo, autosave and recovery path. Project swatches are canvas-scoped metadata with their own undo entry in the chronological canvas history. Applying a swatch copies its colour to the selected object or effect. Image effect colour inputs use RGB, and shadow opacity is separate. Existing projects need no IndexedDB migration. [Image schema](../src/features/icanvas/imageEdits.ts) · [Storage validation](../src/features/icanvas/imagePersistence.ts)

Canvas, card face, presentation, edited thumbnail, sampler and visual export use the same Canvas 2D pipeline. Browser decoding supplies the oriented source. Straighten rotates within those source bounds, then the renderer applies a normalised crop with transparent uncovered corners. A rectangular image contains the crop in its existing frame, while geometric masks cover their target and allow local scaling and offsets. Circles use the shortest side of the image frame. Manual brightness and contrast precede saturation, warmth and tint. Warmth balances red and blue, and tint balances green against red and blue. The chosen Look blends with that result in sRGB at the selected intensity. Geometric clipping precedes alpha-based shadow and outline. Effects use image-local lengths, so canvas zoom and rotation carry them with the image. Connector endpoints continue to use object bounds. [Rendering pipeline](../src/features/icanvas/imageRendering.ts)

Edited images on the canvas request a resolution based on the settled zoom and device pixel ratio, with device scale capped at 2×. The preview allocator limits each raster to 2,304 pixels on its longest edge and 3 Mi pixels (12 MiB RGBA). All mounted edited stage previews share 6 Mi pixels (24 MiB RGBA). A single paint per frame can temporarily add one output raster, one scratch raster and one colour buffer, for a conservative 60 MiB application-managed stage limit. Culling releases the preview buffers. The browser controls source decoding and graphics memory separately. The 128-pixel edited thumbnails, 96-pixel Look samples, crop UI and bounded static exports use their own rendering paths. [Preview allocator](../src/features/icanvas/imagePreview.ts)

Changing link revision or relinking rebuilds the image from the resolved source. A changed source dimension prompts the user to update the crop. Each compact stack mounts only its displayed face. Edited previews of animated sources render a still frame.

## Audio waveform player

The active face owns one HTML audio element. It supplies playback, seek, volume and elapsed time in both display modes. WaveSurfer 8.1.0 receives that external element and Croft's precomputed peaks, draws bars and progress, and releases its listeners when the waveform view closes. Appearance changes update its colour options. Card transforms and the canvas camera affect layout and pointer coordinates. Hiding a face, culling the player, switching projects or removing the source pauses the element. Compact keeps the same media element on a visible face and uses a simple seek slider. [Player](../src/features/icanvas/AudioPlayer.tsx) · [WaveSurfer](https://github.com/katspaugh/wavesurfer.js/releases/tag/8.1.0)

Web Audio generates up to 2,048 bins using the strongest absolute sample across channels in each bin. This retains brief peaks and opposite-phase channels. The service caps encoded input at 24 MiB, duration at 180 seconds, the native PCM estimate at 96 MiB, and concurrent work at one decode and six queued sources. Some source formats reach the PCM cap before the duration cap. Cache entries are keyed by algorithm and original asset revision. Linked keys also include the validated file's last modification time. The in-memory cache holds up to 64 sources, about 512 KiB of peak arrays, and stores no decoded PCM or cached user audio on disk. A native decode already in progress can finish before cancellation takes effect. Croft offers Compact playback when the browser can play a track whose peaks are unavailable or disagree with its playback duration. [Peak service](../src/features/icanvas/audioPeaks.ts)

Audio display mode and colours are per Front or Back and use the normal object history and writer lock. Waveform data, playhead, volume and playback status are transient. Editable version 4 carries appearance for live projects and snapshots, while original imported bytes and linked-file permissions follow existing package rules. Visual exports render unplayed bars, the starting playhead, title and duration, or label an unavailable waveform. The visual audio allowance is 96 bars per instance, 256 instances per export and up to six cold source checks in a five-second budget. Playback positions and audio bytes are excluded from static files. [Audio schema](../src/features/icanvas/audioAppearance.ts) · [Visual export](../src/features/icanvas/portability.ts)

## Smartlinks

Smartlinks use the version 5 optional `smartlink` field on a canvas object or on its Back face. The validated record carries a supported provider, canonical URL, provider ID, mode, title and notes. URL parsing is local and accepts only HTTP(S), rejects credentials and non-default ports, and treats unsupported provider routes as ordinary bookmark cards. User-facing names, notes, URLs and provider IDs participate in local search. Smartlink cards keep their object ID and geometry when the display mode changes. Front and Back records are independent and both travel with stack members. Existing version 1–4 records need no migration. [Schema and URL parser](../src/features/icanvas/smartlinks.ts) · [Storage validation](../src/features/icanvas/imagePersistence.ts)

Provider permissions live in origin-scoped browser localStorage, separate from canvas objects and backups. Both providers default to Ask. Load Once is held in page memory and keyed to object, face, provider and URL. Always Allow is an explicit provider-specific preference. Block and Ask tear down the visible provider frame and clear one-time grants. Imported packages, Save VC restores and workspace backups never grant permission. A user can manage these choices in Settings → Privacy → External Content. Provider permissions are separate from the single-writer lock; a read-only project tab can still display a provider after the viewer grants access.

YouTube uses its privacy-enhanced `youtube-nocookie.com/embed/` frame. X uses the official `platform.twitter.com/embed/Tweet.html` frame directly, with Do Not Track enabled; Croft does not run `widgets.js` or other third-party JavaScript in its application window. The app CSP allows only these frame hosts and keeps its script policy same-origin. The provider runs in a cross-origin sandbox, so it cannot read Croft's project or privileged document. The embed frame is absent before consent. Croft does not fetch previews, favicons or page metadata. Other URLs remain local bookmark cards and never use live embeds.

Live embeds mount only for the active face of a visible, expanded, on-screen object once it reaches the minimum play size and a four-frame limit has room. Hidden, buried, collapsed, offscreen, paused, offline, or overlay-suspended embeds are not mounted. Croft does not autoplay media. Link Only and Preview Card do not contact providers. A provider request shares ordinary network information such as the device IP address with that provider and its delivery services. X embed requests use DNT, but provider-side network logging and cookies remain outside Croft's control. Offline cards retain their URL and notes and offer Retry, Copy Link and Open Original.

Editable project packages and workspace backups retain references, notes, modes and both faces, but never remote media or provider permissions. Static SVG/PNG/JPG/PDF output emits local labelled cards with saved text and URLs; it includes no external URLs as active links, scripts or iframes. Portable package inventory reports reference counts. Package schema version 5 and workspace-backup version 5 carry Smartlinks while readers continue accepting older formats. [Portable output](../src/features/icanvas/portability.ts) · [Workspace backup](../src/features/icanvas/workspaceBackup.ts)

## Storage and save semantics

`storage.ts` opens `croft-icanvas`, database version 1, with `projects`, `assets`, `recoveries`, and `versions`. Projects carry stable references to asset records. Imported media is stored as Blobs, and linked media stores validated metadata and an optional browser handle. Versions and recovery snapshots reuse asset IDs. Before any IndexedDB write the application requires ownership of the `croft-icanvas-writer` Web Lock. Other tabs on the same origin and profile stay read-only and can request editing again after the writer closes. A successful takeover reloads the committed head before accepting input. Unsupported lock contexts remain read-only. Browser permissions, quotas and eviction still apply. [Storage](../src/features/icanvas/storage.ts) · [Writer lock](../src/features/icanvas/writerLock.ts) · [IndexedDB specification](https://w3c.github.io/IndexedDB/)

| Operation | Effect |
| --- | --- |
| Autosave | `useCanvasProjects` debounces pending changes by two seconds and serialises writes. `Saved` reflects a completed IndexedDB transaction. A failed write leaves pending work available to retry. |
| Recovery | A five-minute timer checkpoints changed projects in the open app. Retention is ten per project. Recovery is separate from immutable numbered versions. |
| Save | Flushes the pending head and clears recovery entries for the current project after a successful write. |
| Save VC | Creates a numbered local checkpoint of the canvas and its descendants. Restoring a version keeps the pre-restore state as a checkpoint. |
| Save As | Creates a separate local copy with fresh project, object and edge IDs. The selected scope can include the descendant tree. Immutable media IDs can be reused. |
| Export | Downloads a file through the browser. It has no effect on the current head, checkpoints, or local project identity. |
| Workspace backup | Reads all four IndexedDB stores in one transaction after successful flush in the editing tab. Writes `.croftbackup` to a user-chosen file, with a 64 MiB metadata header cap and 1 MiB media chunks. Restore validates the data and adds new IDs atomically. |

## Media boundary and portable packages

- File-pick and drop paths flow through `ImportDialog.tsx`. Import validates names, size and type markers, rejects known active content, and uses browser decoding for raster images. The picker supports up to 100 MiB for a file and 250 MiB for copied files in a batch. Link In needs a usable permission-bearing handle. Fallback file input supports copying, and unavailable links have a relink action. Media uses local object URLs. Attached files can be downloaded without embedding their document code. [Import](../src/features/icanvas/ImportDialog.tsx) · [Media rendering](../src/features/icanvas/CanvasVisuals.tsx)
- `portability.ts` emits stored ZIP containers with `manifest.json` and numbered `assets/*.bin` entries. Packages and workspace backups with Smartlinks use version 5; audio appearance uses version 4, image edits and swatches use version 3, and cards/stacks use version 2. Croft reads versions 1–5. The native reader checks ZIP paths and bounds, verifies embedded SHA-256 digests and validates references before remapping IDs. Both faces and all stack members are enumerated, including hidden members. Portable packages omit file handles, browser permissions, version/recovery history and canvases outside the selected scope. Linked attachments can be relinked after import. [Portability](../src/features/icanvas/portability.ts) · [Round-trip verification](ICANVAS_EXPORT_QA.md)
- Editable export is bounded to 120 MiB overall, 8 MiB of manifest and 40 MiB per embedded file. Its preflight lists affected media, versions and recoveries excluded from the export, and target references outside the chosen scope. The full `.croftbackup` path can carry media beyond the portable limits by reading and hashing fixed-size chunks. It includes Trash, versions, recovery entries and copied assets. Linked targets retain metadata without handles, paths or bytes. The browser must support saving to a selected writable file. [Portable export](../src/features/icanvas/portability.ts) · [Workspace backup](../src/features/icanvas/workspaceBackup.ts)
- SVG is generated with escaped text and local, supported raster content. PNG and JPG rasterise that SVG with the browser Canvas API. PDF fits a raster image within one A4 page. These formats show the visible face and current compact or fanned arrangement. Descendant visual exports bundle separate files per canvas, up to 100 canvases. Rendering scales the image down to fit a bound of approximately 4,096 px per side and 12 megapixels. Supported audio can appear as a static waveform. Video and unavailable media use labelled visual placeholders. Broad-canvas text fidelity and multi-page tiling remain separate work. [Export implementation](../src/features/icanvas/portability.ts) · [Browser export checks](ICANVAS_EXPORT_QA.md)
- Edited photos use a fresh PNG within SVG, bounded to 1,600 pixels per side with 16 MiB source and 48 MiB total embedded image markup limits. This includes visible effect padding, and the embedded PNG excludes source pixels removed by crop or masking. A missing or unreadable edited source blocks visual export. For recoverable crops and original bytes, use an editable package or workspace backup. Cropping is an editing operation and carries no redaction guarantee. [Export policy](../src/features/icanvas/portability.ts)

## Verification

Run `npm run build` and `node --test tests/*.test.mjs` from `croft-ui`. The IndexedDB, dialog and export tests in `tests/` use an isolated Chrome context. The export fixture verifies file signatures, image decoding, PDF page metadata, and an editable reimport with new IDs and the original attachment bytes. Large-scene performance, storage eviction, browser-specific link permissions, and restore after profile loss require their own evidence. [Export QA commands](ICANVAS_EXPORT_QA.md)
