# iCanvas feature matrix

Evidence is from the local Windows Chromium runs and automated tests in the [QA record](ICANVAS_QA.md). Each row describes the scope of its status.

| Stage and requirement | Status | Evidence and limits |
| --- | --- | --- |
| A · Keep the Croft shell, original mark and five utility controls. Add canvas projects on Home and a separate project tree. | WORKING + TESTED | Browser checked the five utilities, Home, project creation, Ctrl+K and sidebar collapse and restore. The tree uses the same IndexedDB project IDs as cards and routes. [Workspace](../tests/icanvas-workspace.mjs) |
| A · Responsive header, breadcrumbs, compact palette, minimap, inspector and context actions | WORKING + TESTED | Chrome checked 1440, 1024, 768 and 390 px widths, light and dark, and selection. [Workspace](../tests/icanvas-workspace.mjs) |
| A · Dot, line and blank backgrounds, float or park-left toolbar, placement and snap options | WORKING + TESTED | Grid change, minimap and zoom controls in Chrome. Smart/Free primitives in Node. Toolbar modes and gesture combinations have separate coverage gaps below. [Workspace](../tests/icanvas-workspace.mjs) · [Geometry](../tests/icanvas-geometry.test.mjs) |
| A · Drag floating toolbar to a custom position and persist it per canvas | WORKING + TESTED | Chromium verified dragging, saving and reopening the same toolbar position. Parked mode uses the left edge. [Scale and input](../tests/icanvas-scale.mjs) |
| B · Pan, pointer-anchored zoom, object bounds, fit, minimap, viewport culling | WORKING + TESTED | Zoom spans 0.25–6,400%. Chromium verified hit-testing on a distant object and camera persistence at both limits. [Geometry](../tests/icanvas-geometry.test.mjs) · [Scale and input](../tests/icanvas-scale.mjs) |
| B · Native multi-touch pinch gesture | WORKING + TESTED | Chromium's input protocol generated two touch points. The world anchor followed their midpoint when scaling and panning together. A physical touchscreen was outside this run. [Scale and input](../tests/icanvas-scale.mjs) |
| B · Text, note, shapes and freehand objects, Direct/Card and editable properties | WORKING + TESTED | Chrome checked text edit, move, resize, rename, locking and layers. Strokes and display switches share the same edit model. [Workspace](../tests/icanvas-workspace.mjs) |
| B · Vector pen width and colour | WORKING + NOT YET TESTED | Strokes have a default stored width and palette editing. Pressure and a width picker are not implemented. |
| B · Selection, marquee, nudge and resize or rotate | WORKING + TESTED | Chrome tested selection, movement, resize and grouped movement. Marquee and keyboard edge cases are tracked in the QA record. [Workspace](../tests/icanvas-workspace.mjs) |
| B · Corner resize snaps to nearby card edges | WORKING + TESTED | With Snap to Objects enabled, the bottom-right handle aligns to nearby horizontal and vertical edges. Show Guides reveals each snap. Alt bypasses snapping. [Resize](../tests/icanvas-resize-snap.mjs) |
| B · Custom object colours, manual edge rotation and selection lock | WORKING + TESTED | The inspector accepts a colour wheel, HEX and RGB. Rotate uses four edge targets, configurable angle steps and Alt for free rotation. Quick-action padlocks show the current state. Chrome verified persistence and undo. [Colour and lock](../tests/icanvas-colour.mjs) · [Rotation](../tests/icanvas-rotate.mjs) |
| B · Move, scale and rotate groups. Ungroup in place. Frame hierarchy, inherited visibility, container picker and auto-grow. | WORKING + TESTED | Chrome verified group movement and ungroup, frame attach/detach/collapse, and rotating and scaling a frame that contains another frame, a group and connected shapes. A single edit reaches each descendant once and undo restores exact positions. [Workspace](../tests/icanvas-workspace.mjs) · [Containers](../tests/icanvas-containers.mjs) |
| B · Geometry-preserving frame transforms and snap to equal gaps | WORKING + TESTED | Frames grow in their own orientation and propagate to ancestor frames without moving children. Resizing containers is proportional to preserve rotated geometry. Geometry tests cover equal gaps alongside and between adjacent items on aligned rows and columns. [Geometry](../tests/icanvas-geometry.test.mjs) |
| B · Redraw auto-grown frames when an object leaves | WORKING + TESTED | Switching an image from a frame to Canvas preserves its world position. The former frame refits around its remaining contents and its pre-growth size. Undo and redo restore the membership and frame bounds together. **Fit frame to contents** can trim excess space in frames saved before pre-growth bounds were recorded. [Workspace](../tests/icanvas-workspace.mjs) |
| C · Nested project metadata, project details, breadcrumb and double-click navigation | WORKING + TESTED | Chrome reached Holiday Ideas → Hotels → Paris Hotels via object tiles and checked breadcrumb navigation. Project names and parent IDs are stored locally. [Workspace](../tests/icanvas-workspace.mjs) |
| C · Reparent projects and recover a trashed branch without dropping descendants | WORKING + TESTED | Reparented Hotels to the top level, checked for ownership-cycle candidates, restored the branch from Trash and verified a reload. [QA](ICANVAS_QA.md) |
| C · Non-owning canvas references and ancestor links | WORKING + TESTED | Chrome linked Paris Hotels to its ancestor, opened the canonical project, and deleted the link tile while the ownership tree remained intact. [Workspace](../tests/icanvas-workspace.mjs) |
| C · Built-in project icons, cover upload and live schematic thumbnails | WORKING + NOT YET TESTED | Project Details accepts common raster covers. Schematic thumbnails are shown in the browser walkthrough. Uploaded cover retention has no dedicated run. |
| C · Uploaded project icon | WORKING + TESTED | Chrome verified PNG bytes in IndexedDB, stored description and display in breadcrumbs and Home across reload. Icon asset references travel with portable exports and full backups. [Containers](../tests/icanvas-containers.mjs) · [Backup](../tests/icanvas-workspace-backup.test.mjs) |
| C · One-click cover capture | NOT IMPLEMENTED | Project Details offers cover file upload. |
| D · Compact/expanded import, per-file choices, batch override, mixed validation and persisted Blobs | WORKING + TESTED | Browser verified mixed allowed / rejected files, truthful Link In controls and reload. Separate IndexedDB test confirmed Blob data. [Dialogs](../tests/icanvas-dialogs.mjs) · [Storage](../tests/icanvas-indexeddb.mjs) |
| D · Raster image decoding and local audio/video playback after batch import | WORKING + TESTED | Chrome decoded PNG, played PCM WAV and VP8 WebM before and after reload, and verified Smart/Free placement and stored byte counts. [Media](../tests/icanvas-media.mjs) |
| D · Browser File System Access Link In and Relink | WORKING + TESTED | Chrome drag produced a real file handle without copying bytes. A real rename and full browser restart exercised missing and permission-prompt states. Relink used a second real handle supplied in place of the Windows chooser and preserved the object and source files. [Linked files](../tests/icanvas-linked-files.mjs) |
| D · Manual OS chooser, native permission dismissal and revocation | WORKING + NOT YET TESTED | Chrome put the stored handle in `prompt` after restart. Tests injected denial in the page and verified the separate permission and retry UI. Live OS chooser and native permission changes remain unverified. |
| D · PDF and other safe file cards | WORKING + TESTED | Ordinary attachments can be imported, downloaded and saved. Files are inert, including PDFs. [Export verification](ICANVAS_EXPORT_QA.md) |
| D · Native PDF attachment rendering | NOT IMPLEMENTED | PDF attachments are available as files. Canvas PDF export is a separate workflow. |
| E · Direction, Connection and Relationship edges, labels and independent visibility | WORKING + TESTED | Geometry endpoints, seeded edge rendering and named relationship editing passed. Edges use local objects, including link tiles, as endpoints. [Geometry](../tests/icanvas-geometry.test.mjs) · [Workspace](../tests/icanvas-workspace.mjs) |
| E · Direct cross-canvas object endpoints, named port routing and advanced edge style | NOT IMPLEMENTED | Relationships can point at a reference tile on the current canvas. |
| F · Ordered Undo/Redo and cap of 50 actions per object | WORKING + TESTED | Atomic operations and interleaving passed in Node. Delete/Undo/Redo passed in Chrome. [History](../tests/icanvas-history.test.mjs) · [Workspace](../tests/icanvas-workspace.mjs) |
| F/G · IndexedDB, two-second autosave, changed-only recovery and durable manual Save | WORKING + TESTED | Browser tests covered rollback, saved media on reload, ten-snapshot cap, recovery restore, and Ctrl+S clearing recovery after successful commit. Virtual-time browser run exercised the real scheduler. [IndexedDB](../tests/icanvas-indexeddb.mjs) · [QA](ICANVAS_QA.md) |
| F · Single writer, read-only tab handoff and draft preservation | WORKING + TESTED | Web Locks gate every IndexedDB write in the current app. Chrome verified a second tab cannot write through the UI or the storage API. Explicit takeover reloads committed work. Failed writes leave an in-memory draft and export or retry options. [Safety](../tests/icanvas-safety.mjs) |
| F · Abrupt browser exit, failed transactions and quota handling | WORKING + TESTED | Chrome process crash and reopen preserved saved head, version and recovery. An injected IndexedDB quota error and an aborted invalid hierarchy write preserved prior data. [Safety](../tests/icanvas-safety.mjs) |
| F · Browser eviction, physical disk exhaustion and failure during commit | WORKING + NOT YET TESTED | Eligibility and outcome depend on browser and OS. Recovery covers stored data only. |
| F · Automatic corrupt-head diagnosis and asset garbage collection across revisions | NOT IMPLEMENTED | Recovery is opened explicitly. Stored assets are retained so versions, recovery and copies keep their references. |
| G · Save VC notes, numbered snapshots, preview and restore with a checkpoint. Save As with remapped descendant IDs. | WORKING + TESTED | Browser and storage tests exercised both. The preview summarises stored objects, edges and counts. [Dialogs](../tests/icanvas-dialogs.mjs) · [Storage](../tests/icanvas-indexeddb.mjs) |
| G · Object-by-object version comparison, revision note editing and bundling linked bytes in Save As | NOT IMPLEMENTED | Versions are immutable. Copies preserve linked asset references and show a dependency warning. |
| H · Existing global Search, local Find, scoped results and jump to objects | WORKING + TESTED | Chrome checked Ctrl+K, Ctrl+F and selected jump result. Hidden results direct users to Layers. [Workspace](../tests/icanvas-workspace.mjs) |
| H · Embedded Croft page cards and their source pages | VISUAL ONLY | Existing Croft documents/database are fixtures. Cards link to their canonical preview route. SubCanvas thumbnails show real stored state. |
| H · Code Playground preview or execution | NOT IMPLEMENTED | Outside this phase. |
| I · Editable `.croft` and ZIP, bounded SVG/PNG/JPG/PDF, package reimport | WORKING + TESTED | Browser inspected downloads, decoded images, used Poppler for PDF, reimported descendants and verified asset bytes and new IDs. | I · Preflight export and separate, streamed workspace backup | WORKING + TESTED | Preflight lists linked and unavailable media, history and reference omissions and size limits. `.croftbackup` preserves copied media, canvas heads, Trash, version checkpoints and temporary recoveries. The test substituted an actual Chrome private filesystem writer for the OS picker. [Backup](../tests/icanvas-workspace-backup.mjs) |
